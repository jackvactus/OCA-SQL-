# Audit du 31 août 2026 (nuit) — banque anglaise reconstruite et liens Oracle

Troisième lot de la journée, après
[AUDIT-2026-08-31.md](./AUDIT-2026-08-31.md) (programmes officiels) et
[AUDIT-2026-08-31-B.md](./AUDIT-2026-08-31-B.md) (sécurité et notation).

Il porte sur les deux constats laissés ouverts la veille — PED-07 et PED-12,
la banque anglaise 1Z0-071 — et sur la qualité des liens sortants vers Oracle.

## 1. La banque anglaise était plus abîmée que l'audit ne le disait

L'analyse précédente signalait deux défauts : aucune question multi-réponses,
et des explications trop courtes. L'examen détaillé en a trouvé **quatre de
plus**, dont deux graves.

| Réf. | Constat | Gravité |
|---|---|---|
| **PED-13** | **67 des 224 questions étaient des doublons reformulés** : même jeu d'options, même clé, énoncé réécrit. La déduplication antérieure n'avait retiré que les doublons **stricts** — 96 sur 320 — et laissé passer toutes les variantes | S2 |
| **PED-14** | **À partir du cinquième module, chaque question renvoyait vers le mauvais module.** Une question sur les opérateurs ensemblistes pointait vers le module DML, une question de sécurité vers le module de révision finale. **137 questions sur 224** étaient concernées | S1 |
| **PED-15** | Questions factuellement cassées : `workbook-q31` demandait les colonnes de `HR.DEPARTMENTS` alors que ses **quatre options citaient `hr.employees`** ; `workbook-q14` interrogeait sur la clé alternative avec l'explication de la clé candidate ; `workbook-q17` posait une question sur les comptes bancaires et expliquait la réponse avec des employés et des départements | S1 |
| PED-07 | Aucune question multi-réponses | S3 |
| PED-12 | 224 explications sur 224 sous 120 caractères — 45 en moyenne, la plupart se contentant de reformuler la bonne réponse | S3 |
| **PED-16** | 62 explications servaient à plusieurs questions à la fois, conséquence directe de PED-13 | S3 |

### Le décalage de modules

Le défaut le plus dommageable, parce qu'il est invisible et qu'il oriente
l'apprenant vers le mauvais chapitre :

| Le fichier disait | Le module est réellement | Les questions traitaient de |
|---|---|---|
| m5 | Group Functions and GROUP BY | Conversion & Conditional Expressions |
| m6 | Joins | Group Functions & Aggregation |
| m7 | Subqueries | Joins & Multiple-Table Queries |
| m8 | Set Operators | Subqueries |
| m9 | Data Manipulation Language | Set Operators |
| m10 | DDL: Creating and Managing Tables | DML & Transactions |
| m11 | Analytic Functions | DDL, Constraints & Schema Objects |
| m14 | Exam Preparation and Strategy | User Security, Privileges & Roles |
| m16 | Sécurité Oracle | Time Zones & DATE/TIMESTAMP |

Un décalage d'un rang de m5 à m11, puis une divergence complète. Le test
existant ne vérifiait que l'**existence** du module, jamais sa pertinence.

## 2. La banque a été reconstruite

Plutôt que de rapiécer 224 entrées abîmées, la banque a été réécrite domaine
officiel par domaine officiel, dans `lib/quiz-data-en-oca.ts` (domaines 1 à 8)
et `lib/quiz-data-en-oca-b.ts` (domaines 9 à 16).
`lib/quiz-data-en-workbook.ts` n'est plus qu'un agrégateur, ce qui évite de
toucher aux quatre pages qui l'importent.

| | Avant | Après |
|---|---|---|
| Questions | 224, dont 67 doublons reformulés | **138, toutes distinctes** |
| Questions multi-réponses | 0 % | **17 %** |
| Explications sous 120 caractères | 224 / 224 | **0 / 138** |
| Longueur moyenne d'explication | 45 caractères | **194 caractères** |
| Position dominante de la bonne réponse | 93 % en A | **27 % au maximum** |
| Sujets | 16, inventés | **16, les domaines officiels** |
| Rattachement au module | 137 faux sur 224 | **0 faux sur 138** |
| Jeux d'options dupliqués | 65 groupes | **0** |

Chaque explication justifie désormais la clé **et** écarte explicitement les
distracteurs — le même standard que les cinq banques d'administration.

> **138 contre 224 n'est pas une perte.** Les 224 comptaient 67 doublons, soit
> 157 questions réelles ; et une bonne part des 157 posait la même notion sous
> deux angles. La couverture des 16 domaines officiels est intégrale.

## 4. Mes propres banques avaient le défaut que je reprochais

Le profilage a montré que les trois banques de spécialisation écrites la veille
avaient **100 % de leurs réponses à choix unique en position A** dans les
données sources.

La permutation à l'exécution neutralise ce biais pour l'apprenant — c'est
testé — mais laisser la donnée dans cet état était incohérent avec ce que
l'audit reproche par ailleurs. 131 questions ont été rebasculées vers B, C et D.

| Banque | Position dominante avant | Après |
|---|---|---|
| 1Z0-084 | 100 % | **26 %** |
| 1Z0-076 | 100 % | **25 %** |
| 1Z0-078 | 100 % | **27 %** |

Opération délicate : la table de traduction anglaise indexe les options par
**position**. Toute permutation côté français devait être appliquée à
l'identique côté anglais, faute de quoi les bonnes réponses ne correspondaient
plus. Le test « la traduction anglaise conserve le nombre d'options et la clé »
a servi de filet, et les 45 tests passent.

## 5. Les liens vers Oracle

### Le défaut

`officialLearningUrl` des trois parcours de spécialisation portait
`mylearn.oracle.com/ou/learning-path/oracle-database-19c-administration/**88357**`
— **le même identifiant numérique pour les trois**. Je l'avais fabriqué et
recopié. Un identifiant inventé a l'air exact et mène l'apprenant sur une page
inexistante : c'est pire qu'un lien général assumé.

### Ce qui a été fait

- Le lien fabriqué est **retiré**, pas remplacé par une autre supposition.
  `officialLearningUrl` devient facultatif : il n'apparaît que pour les trois
  parcours dont l'identifiant de catalogue Oracle University figurait dans le
  dépôt d'origine.
- Un champ **`officialDocsUrl`** est ajouté pour les six parcours, pointant le
  manuel Oracle Database 19c qui couvre le programme. Ces raccourcis sont les
  URL Oracle les plus stables qui existent, et souvent plus utiles à la révision
  qu'une fiche de catalogue :

| Parcours | Manuel 19c |
|---|---|
| 1Z0-071 | `sqlrf/` — SQL Language Reference |
| 1Z0-082 | `admin/` — Database Administrator's Guide |
| 1Z0-083 | `multi/` — Multitenant Administrator's Guide |
| 1Z0-084 | `tgdba/` — Database Performance Tuning Guide |
| 1Z0-076 | `sbydb/` — Data Guard Concepts and Administration |
| 1Z0-078 | `racad/` — Real Application Clusters Administration |

- Un lien vers le **parcours de certification Oracle** complète la carte.
- Chaque lien porte un `aria-label` annonçant l'ouverture dans un nouvel onglet,
  et l'icône est masquée aux lecteurs d'écran.

### Ce qui n'a pas pu être fait

L'environnement est **hors ligne** : deux tentatives de vérification par requête
HTTP ont expiré, comme les polices Google pendant les builds. **Les URL n'ont
donc pas pu être testées en direct.**

Les URL d'examen suivent la forme canonique documentée par Oracle —
`education.oracle.com/<intitulé-en-minuscules-tirets>/pexam_<CODE>` — et le
segment de titre est dérivé mécaniquement de l'intitulé officiel figurant sur
la fiche. C'est une déduction solide, ce n'est pas une vérification.

`tests/oracle-links.test.ts` verrouille tout ce qui est vérifiable hors ligne :
HTTPS, domaine Oracle, forme canonique, présence du bon code d'examen, manuel
19c, et surtout **absence de lien recopié d'un parcours à l'autre** — le test
qui aurait attrapé l'identifiant `88357`.

## 6. Incident de dépendance à signaler

En cours de session, `npm audit fix` a appliqué une **montée majeure vers
Next 16.3.3** que je n'avais pas demandée et dont sa propre sortie disait
qu'elle exigeait `--force`. Ce dépôt est en Next 13 : le typage a immédiatement
cassé sur `cookies()`, devenu asynchrone.

Revenu à `next@13.5.11` et `postcss@8.4.31`, tous deux épinglés. `npm audit`
affiche **0 critique et 0 modérée**, 5 hautes restantes documentées au §2 de
l'audit précédent.

À retenir : `npm audit fix` peut modifier `package.json` au-delà de ce que sa
sortie annonce. La CI exécutant `npm ci`, une dérive de ce type serait
détectée — mais après coup.
