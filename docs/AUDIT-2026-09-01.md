# Audit du 1er septembre 2026 — l'erreur `removeChild` et ses causes

Ce lot part de deux symptômes signalés en production :

> Échec de l'exécution de 'removeChild' sur 'Node' : le nœud à supprimer n'est
> pas un enfant de ce nœud.

et « quand on clique sur le cours d'un autre type de cours, ça fait erreur ».

**Les deux avaient la même cause.**

---

## 1. Le diagnostic

Le HTML interdit le contenu interactif à l'intérieur d'une ancre. Un `<button>`
écrit dans un `<a>` est donc **reparenté par le navigateur** au moment du
parsing : le bouton sort de l'ancre, et le DOM réel cesse de correspondre à
l'arbre que React a rendu côté serveur.

Tant que rien ne bouge, l'écart passe inaperçu. À la première réconciliation —
c'est-à-dire à la première **navigation** — React tente de retirer un nœud qui
n'est plus là où il croit, et lève `removeChild`. En production, Next.js
transforme cette exception en « Erreur d'application : une exception côté
client s'est produite ».

Cela explique les deux symptômes d'un coup : l'erreur ne survient pas sur la
page, elle survient **quand on la quitte** — donc précisément « quand on clique
sur un cours ».

### L'ampleur

**30 occurrences**, réparties sur 16 fichiers :

| Fichier | Occurrences |
|---|---|
| `app/(app)/tracks/[trackId]/page.tsx` | 5 |
| `app/(app)/curriculum/[sessionId]/page.tsx` | 3 |

| `app/(app)/activity/page.tsx` | 2 |

Les pages d'erreur elles-mêmes étaient concernées : une exception y menait, et
la page censée la rattraper en produisait une seconde.

## 2. Le correctif

Le composant `Button` accepte déjà `asChild`, qui s'appuie sur le `Slot` de
Radix : le bouton ne rend alors plus de `<button>`, il transmet ses styles à
son enfant. Un seul élément est produit — une ancre stylée en bouton — et le
navigateur n'a plus rien à reparenter.

```tsx
// AVANT — <a><button></button></a>, reparenté par le navigateur
<Link href="/quiz">
  <Button size="sm" variant="outline">…</Button>
</Link>

// APRÈS — une seule ancre, stylée en bouton
<Button asChild size="sm" variant="outline">
  <Link href="/quiz">…</Link>
</Button>
```

Les 30 occurrences ont été converties : 21 par transformation automatique, 9 à
la main, leur forme échappant au motif (bouton sur une seule ligne, ou balise
ouvrante répartie sur plusieurs lignes).

## 3. Le test qui empêche le retour

`tests/html-nesting.test.ts` parcourt tous les `.tsx` de `app/` et
`components/` et refuse :

- un `<Button>` ou `<button>` en premier enfant d'une ancre, sans `asChild` ;
- une ancre imbriquée dans une autre ancre.

> **Le test a d'abord raté cinq cas.** Son expression régulière exigeait un
> espace ou un chevron après `<a`, alors qu'une balise ouvrante répartie sur
> plusieurs lignes laisse `<a` seul sur sa ligne. Le `$` ajouté à
> l'alternance — `/^<(a|Link)(\s|>|$)/` — ferme cet angle mort. C'est
> l'illustration exacte de pourquoi un test doit être vérifié contre un cas
> connu avant d'être cru sur parole.

## 4. Huit avertissements qui étaient huit bugs

Les avertissements `react-hooks/exhaustive-deps` traînaient depuis le premier
audit, régulièrement écartés comme « préexistants ». Ils décrivaient un défaut
réel.

`getLocalizedModules(locale)` renvoie le contenu dans la langue courante. Or
les mémos qui l'exploitaient ne le déclaraient pas en dépendance :

```tsx
const modules = getLocalizedModules(locale);
const grouped = useMemo(() => { /* lit modules */ }, []);   // ← jamais recalculé
```

**Conséquence : changer de langue ne changeait pas le contenu des cours.** Le
titre de la page se traduisait, la liste des modules non.

Déclarer simplement la dépendance aurait fait recalculer à chaque rendu, car
`getLocalizedModules` renvoie un tableau neuf à chaque appel. `modules` est donc
d'abord mémoïsé sur la locale, puis déclaré :

```tsx
const modules = useMemo(() => getLocalizedModules(locale), [locale]);
const grouped = useMemo(() => { /* lit modules */ }, [modules]);
```

Corrigé dans `courses/page.tsx`, `courses/[moduleId]/page.tsx`,
`dashboard/page.tsx` et `flashcards/page.tsx`.

**`npm run lint` affiche désormais « No ESLint warnings or errors ».** C'est la
première fois sur ce dépôt.

## 5. Ressources externes

Deux liens demandés, intégrés — et centralisés plutôt que recopiés.

`lib/external-resources.ts` décrit chaque ressource avec un libellé **et une
phrase disant ce qu'on y trouve** : un lien nu oblige à ouvrir l'onglet pour
savoir s'il intéresse.

| Ressource | Adresse | Où elle apparaît |
|---|---|---|
| **Certifications Oracle — portail officiel** | `oracle.com/education/certification/` | Page d'un parcours, page des cours, page du curriculum |
| **Parcours Oracle Database** | `education.oracle.com/oracle-certification-path/pFamily_32` | Page d'un parcours, page du curriculum |
| **FreeSQL — console SQL en ligne** | `freesql.com` | Page d'un parcours, page des cours, curriculum, bac à sable |

Sur le bac à sable, le lien est accompagné d'une mise au point utile :
l'environnement intégré **simule** un sous-ensemble d'Oracle SQL sur des données
d'exemple ; pour ce qu'il ne couvre pas, il faut un vrai moteur.

Le rendu passe par `components/external-resource-links.tsx`, qui tient deux
règles à un seul endroit : le motif `asChild` — pour ne pas recréer le défaut
corrigé au §2 — et l'annonce aux lecteurs d'écran de l'ouverture d'un nouvel
onglet, l'icône leur étant masquée.

La carte des ressources de la page d'un parcours a été refaite avec ce
composant, ce qui supprime cinq ancres écrites à la main.
