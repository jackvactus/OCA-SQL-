## 2. La faille critique et ce qu'elle permettait

`middleware.ts` porte la frontière d'authentification : toute page hors `/`,
`/login` et `/register` exige une session valide. Or **CVE-2025-29927** permet
de faire sauter entièrement l'exécution du middleware en ajoutant un en-tête
`x-middleware-subrequest` à la requête. Un visiteur non authentifié pouvait
donc atteindre le rendu de `/dashboard`, `/admin` et le reste.

La version installée était `next@13.5.1`, **épinglée sans accent circonflexe**,
ce qui empêchait `npm audit fix` de corriger : il signalait « outside the stated
dependency range » sans que la cause soit évidente.

| | Avant | Après |
|---|---|---|
| Critiques | 1 | **0** |
| Hautes | 13 | 5 |
| Modérées | 4 | **0** |
| **Total** | **18** | **5** |

Les 5 restantes se répartissent ainsi :

- `minimatch`, `@typescript-eslint/parser`, `@typescript-eslint/typescript-estree` — dépendances transitives d'**ESLint**, présentes au build uniquement, jamais livrées au navigateur ni exécutées en production.
- `next`, `postcss` — corrigeables seulement par une montée à **Next 16**, changement de version majeure qui demande une migration à part entière. Les CVE restantes portent sur l'optimiseur d'images et les Server Actions, deux fonctionnalités que ce projet n'utilise pas.

La CI échoue désormais sur toute vulnérabilité **critique** (`npm audit --audit-level=critical`).

## 3. La notation d'examen passe côté serveur

### Ce qui se passait

```
navigateur                              serveur
  │ importe les 885 questions
  │ avec leurs correctIndexes
  │ tire, corrige, calcule le score
  └── POST /api/progress/exam ────────▶ enregistre {score: 63, total: 63}
                                        (bornes vérifiées, véracité non)
```

Deux problèmes distincts : les corrigés étaient **lisibles avant de composer**,
et le score était **déclaratif**.

### Ce qui se passe maintenant

```
navigateur                              serveur
  │                                     tire les questions
  │                                     mémorise l'ordre des options
  │◀── POST /api/exam/start ──────────  renvoie énoncés + options + answerCount
  │                                     (aucun corrigé)
  │ compose
  └── POST /api/exam/submit ──────────▶ recharge le tirage mémorisé
                                        corrige, enregistre le score
  │◀────────────────────────────────── renvoie score + corrigés
```

- Nouvelle table `exam_sessions` : questions tirées, permutation des options, expiration, score.
- `answerCount` remplace `correctIndexes` pendant l'épreuve : l'énoncé annonce toujours « choisissez deux réponses », mais **pas lesquelles**.
- Une copie ne peut être remise qu'une fois ; au-delà du temps imparti, la session est close plutôt que laissée rejouable.
- `/api/progress/exam` répond désormais **410 Gone** avec la raison, plutôt que de disparaître : la cause reste lisible dans les journaux si un onglet ancien l'appelle encore.

### Politique de correction

La notation est stricte : une réponse contenant un index invalide, hors bornes
ou répété est comptée **fausse**, elle n'est pas « réparée ». Un client conforme
n'en produit jamais ; réparer silencieusement une entrée aberrante masquerait le
problème. Deux tests écrits pour cette règle ont d'ailleurs **échoué à la
première exécution** et révélé que la première version filtrait au lieu de
rejeter : `[2, 99, -1]` marquait un point.

## 4. Les questions quittent le bundle client

La page d'examen était un composant client qui importait `getQuestionBank` —
donc les 885 énoncés et leurs corrigés — uniquement pour afficher « 306
questions disponibles ».

Elle est scindée : `app/(app)/exam/page.tsx` devient un composant **serveur**
qui calcule les tailles de banque et ne transmet que ces chiffres à
`components/exam-client.tsx`.

| Page | Premier chargement avant | Après |
|---|---|---|
| `/exam` | 551 kB | **128 kB** |
| `/quiz` | 575 kB | 577 kB (inchangé, délibérément) |

Soit **77 % de moins** sur la page d'examen : ce qui a disparu du bundle, ce
sont précisément les 885 énoncés et leurs corrigés.

La page `/quiz` conserve sa banque locale, et c'est délibéré : un entraînement
qui affiche la correction immédiatement n'a pas la même exigence qu'un examen
blanc noté.

## 5. Limitation de débit

`lib/rate-limit.ts` — fenêtre glissante en mémoire, avec blocage.

| Route | Clé | Limite | Fenêtre | Blocage |
|---|---|---|---|---|
| `/api/auth/login` | adresse IP | 20 | 10 min | 15 min |
| `/api/auth/login` | adresse e-mail | 8 | 10 min | 15 min |
| `/api/auth/register` | adresse IP | 5 | 1 h | 1 h |
| `/api/exam/start` | utilisateur | 30 | 1 h | 15 min |
| `/api/exam/submit` | utilisateur + IP | 60 | 1 h | — |

Deux fenêtres complémentaires sur la connexion : l'une freine une adresse qui
balaie beaucoup de comptes, l'autre protège un compte visé depuis plusieurs
adresses. Le compteur est incrémenté **avant** tout appel à bcrypt, pour que la
limite tienne même si l'attaquant cherche à saturer le processeur.

**Limite assumée** : l'état vit dans le processus. Derrière plusieurs
instances, chacune applique sa propre fenêtre — la protection est divisée par
le nombre d'instances. Suffisant pour freiner une attaque automatisée depuis
une seule adresse ; une protection réellement distribuée demanderait Redis ou
le pare-feu applicatif de l'hébergeur.

## 6. Tests et intégration continue

`npm test` — 36 tests, sans aucune dépendance nouvelle : le lanceur natif de
Node, exécuté par `tsx` déjà présent.

| Fichier | Ce qu'il verrouille |
|---|---|
| `tests/quiz-data.test.ts` | Identifiants uniques, ≥ 3 options, options non répétées, clés dans les bornes, explications non triviales, énoncés non dupliqués, rattachement à un module ou une session existante, cohérence FR/EN des clés, traduction à 100 % |
| `tests/quiz-shuffle.test.ts` | La permutation conserve les options, fait suivre les bonnes réponses, garde les index triés, et **corrige effectivement** le biais de position des données sources |
| `tests/exam-session.test.ts` | La correction serveur : copie parfaite, copie vide, réponse partielle, toutes options cochées, index dupliqués, hors bornes, non entiers, question disparue de la banque, rattachement par position |
| `tests/rate-limit.test.ts` | Limite, blocage, isolation entre clés, glissement de la fenêtre, extraction de l'adresse cliente |

`.github/workflows/ci.yml` enchaîne typage, lint, tests, `npm audit --audit-level=critical` et build à chaque poussée.

Les tests ont trouvé **quatre défauts réels** dès leur première exécution : les
deux énoncés dupliqués, les trois explications triviales, et les deux bugs de
ma propre correction serveur. C'est exactement ce qu'on attend d'eux.

## 8. Migration à appliquer

La table `exam_sessions` est nouvelle. Avant de déployer :

```bash
npm run db:migrate
```

Le script est idempotent (`create table if not exists`) : il peut être rejoué
sans risque sur une base déjà à jour.

## 9. Ce qui reste, et pourquoi

**PED-07 / PED-12 — la banque anglaise 1Z0-071.** 224 questions, aucune
multi-réponses, 224 explications trop courtes, 16 sujets seulement. C'est un
travail de réécriture de contenu, pas un correctif : il mérite d'être traité
comme un lot à part, avec la même exigence que les cinq banques
d'administration — qui, elles, n'ont aucun de ces défauts.

**I18N-01 — `modules-data.ts`.** La version anglaise des 18 modules reste une
pseudo-traduction obtenue par rechercher-remplacer. Même remarque : c'est une
traduction à refaire, pas un bug à corriger.

**LEG-01 — les documents sources.** `docs/1Z0-071.pdf` est un recueil de type
*exam dump*. Le sortir du dépôt est une décision d'éditeur, pas un correctif
technique : je ne l'ai pas prise à votre place.
