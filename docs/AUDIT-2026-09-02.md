# Audit du 2 septembre 2026 — parcours courant, moteur SQL, assistant

Trois demandes, trois défauts distincts. Le premier était un bug de navigation, le
deuxième un moteur qui refusait ce que le cours enseigne, le troisième une
fonctionnalité absente. Ce document dit ce qui a été trouvé, ce qui a été fait, et
ce qui reste à faire.

**Vérifications de fin de lot :** `tsc` 0 erreur · ESLint 0 avertissement ·
**108 tests** au vert (47 avant ce lot) · `next build` réussi.

---

## 1. Le bouton « continuer » ramenait toujours au SQL

### Le constat

Six parcours de certification sont proposés. Le bouton de reprise du tableau de
bord pointait en dur vers `/courses`, c'est-à-dire les 18 modules SQL. Un
apprenant inscrit sur Data Guard, RAC ou Tuning était donc renvoyé sur le SQL à
chaque reprise.

La cause n'était pas une erreur d'adresse : **aucune notion de parcours courant
n'existait dans l'application**. Rien, nulle part, ne mémorisait le parcours suivi.
Le tableau de bord, le quiz et l'examen retombaient chacun sur le même défaut.

### Le correctif

Le parcours est mémorisé dans un cookie, sur le modèle déjà retenu pour la langue :
un seul point de vérité, lu côté serveur par `getCurrentTrack()` et côté client par
`useCurrentTrack()`, sans route d'API à maintenir.

| Fichier | Rôle |
|---|---|
| `lib/current-track.ts` | Cookie, validation de l'identifiant, `resolveNextStep()`, `trackProgress()` |
| `lib/get-current-track.ts` | Lecture serveur |
| `components/track-provider.tsx` | Contexte client, écriture du cookie |
| `components/remember-track.tsx` | Consulter un parcours le rend courant |

`resolveNextStep()` ne renvoie pas une adresse fixe mais **l'endroit où reprendre
dans ce parcours** : prochain module incomplet pour le SQL, prochaine session de
cursus pour les cinq autres.

Conséquences visibles :

- le tableau de bord annonce où l'on reprend, avec le code d'examen et
  l'avancement, au lieu d'un « continuer » aveugle ;
- les sélecteurs du quiz et de l'examen s'ouvrent sur le parcours suivi ;
- la page des cours, qui reste celle du SQL, le signale quand on suit un autre
  parcours et propose le retour.

## 2. Le bac à sable refusait quatre des seize domaines de l'examen

### Le constat

Le moteur SQL vivait dans le composant de page — 1 484 lignes — et n'acceptait
qu'un `SELECT` avec `WHERE`, `ORDER BY` et une limite de lignes. Il rejetait
explicitement `GROUP BY`, les jointures et les agrégats. Aucune fonction, aucune
sous-requête, aucun opérateur ensembliste.

C'est-à-dire que **le bac à sable refusait précisément ce que le cours enseigne** :
« Using Single-Row Functions », « Reporting Aggregated Data Using the Group
Functions », « Displaying Data from Multiple Tables Using Joins » et « Using
Subqueries to Solve Queries » sont quatre des seize domaines officiels du 1Z0-071.

### Le correctif

Moteur réécrit et sorti de la page vers `lib/sql-sandbox` (2 095 lignes :
tokenizer, parser par descente récursive, évaluateur). Il couvre désormais :

| Domaine | Couverture |
|---|---|
| Projection, alias, `DISTINCT` | oui |
| Expressions, `CASE`, `DECODE` | oui |
| Fonctions mono-ligne | 40 fonctions |
| Agrégats, `GROUP BY`, `HAVING` | oui |
| Jointures interne, externe, croisée, naturelle, `USING`, auto-jointure | oui |
| Sous-requêtes scalaires, `IN`, `EXISTS` corrélées | oui |
| `UNION`, `UNION ALL`, `INTERSECT`, `MINUS` | oui |
| Tri, `NULLS FIRST/LAST`, `OFFSET`, `FETCH` | oui |

**Les pièges d'Oracle sont reproduits fidèlement**, puisque c'est ce qu'on vient
vérifier dans un bac à sable de certification :

- `NULL` se propage dans l'arithmétique mais **pas** dans la concaténation ;
- `SUBSTR` commence à la position 1, pas 0 ;
- `INSTR` renvoie 0 quand il ne trouve pas, pas `NULL` ;
- `NVL2` renvoie son deuxième argument quand le premier **n'est pas** nul ;
- `ROUND(x, -1)` agit sur les dizaines ;
- `COUNT(*)` compte les lignes, `COUNT(colonne)` ignore les `NULL` ;
- un agrégat dans `WHERE` lève `ORA-00934` ;
- `NOT IN` avec un `NULL` dans la liste ne rend aucune ligne.

Les refus expliquent leur raison : le DML est refusé parce que le jeu de données
est partagé, `LIMIT` parce qu'Oracle attend `FETCH FIRST`, une table inconnue
liste les tables disponibles.

**50 tests** couvrent le moteur. L'un d'eux a échoué à la première exécution et a
révélé un défaut réel : les sous-requêtes corrélées ne recevaient pas la ligne
externe, donc `EXISTS` ne pouvait pas fonctionner.

Les 13 exemples de la page ont été refaits, un par notion, et chacun dit **ce
qu'il démontre** plutôt que ce qu'il fait. La page passe de 1 484 à 718 lignes.

## 3. L'assistant

### Ce qui a été demandé et ce qui a été livré

L'assistant est livré en **deux moitiés** : l'interface, complète, et la production
de la réponse, laissée en point d'extension — c'est le périmètre retenu, aucune clé
d'API n'étant disponible.

| Fichier | Lignes | Rôle |
|---|---|---|
| `components/assistant/orb.tsx` | 83 | Le point lumineux |
| `components/assistant/panel.tsx` | 188 | Le panneau de discussion |
| `components/assistant/transcript.tsx` | 175 | Rendu d'un échange, sources, blocs SQL |
| `components/assistant/assistant.tsx` | 114 | Orchestration, réseau, raccourcis |
| `app/(app)/assistant/page.tsx` | 176 | Page d'audit — la transcription |
| `app/api/assistant/ask/route.ts` | 86 | Route serveur, limitation de débit, journalisation |
| `app/api/assistant/transcript/route.ts` | 38 | Lecture et suppression de la transcription |
| `lib/assistant/types.ts` | 68 | Contrat des échanges |
| `lib/assistant/answer.ts` | 100 | **Point d'extension** |
| `lib/assistant/audit.ts` | 125 | Persistance de la transcription |
| `lib/assistant/strings.ts` | 97 | Textes bilingues |

### Le point lumineux

Trois couches superposées — halo diffus, onde qui se propage, cœur net — animées à
des rythmes décalés. C'est ce décalage qui donne l'impression de lumière ; une
seule couche qui grossit et rétrécit donne un bouton qui clignote.

Il reste un vrai `<button>` : il se tabule, s'annonce aux lecteurs d'écran
(`aria-label`, `aria-expanded`, `aria-controls`), garde un anneau de focus visible,
et ses couches décoratives sont `aria-hidden`.

**Sous `prefers-reduced-motion: reduce`, les animations s'arrêtent.** Un point qui
pulse en permanence dans un coin de l'écran est exactement ce que ce réglage
demande de supprimer. Deux tests verrouillent ce comportement, parce qu'il est
facile à perdre lors d'une refonte de la feuille de style.

Ctrl/Cmd + K ouvre et ferme, Échap ferme.

### L'audit et la transcription

Chaque échange est écrit **côté serveur** dans `assistant_messages` : question,
réponse, sources, extraits SQL, page d'où la question a été posée, parcours,
langue, horodatage. Un client ne peut donc pas fabriquer une ligne d'historique.

La page `/assistant` offre deux lectures du même journal :

- **Conversation** — les échanges tels qu'ils se sont déroulés, avec la page
  d'origine de chaque question ;
- **SQL proposé** — les seules requêtes, dédoublonnées, chacune copiable et
  exécutable. C'est ce qu'on revient vérifier : une requête suggérée doit pouvoir
  être relue hors du fil de discussion qui l'a produite.

Le bouton « exécuter dans le bac à sable » passe la requête par `/sandbox?q=…` ;
la page la charge, l'exécute, puis retire le paramètre de l'URL pour qu'un
rafraîchissement n'écrase pas ce que l'apprenant vient d'écrire.

L'apprenant peut effacer sa propre transcription : la trace lui appartient.

### Le comportement par défaut, et pourquoi il est ainsi

Tant qu'aucune logique n'est branchée, `answerQuestion` renvoie
`unavailable: true` avec un message explicite, **sans source ni SQL inventés**, et
l'interface affiche une pastille « Non configuré ».

C'est délibéré. Sur une plateforme de certification, une réponse fausse mais
assurée coûte un examen : mieux vaut pas de réponse qu'une réponse fabriquée. Un
test vérifie que l'indicateur `isAssistantConfigured()` et le champ `unavailable`
ne peuvent pas se contredire — les deux mentent ensemble ou disent vrai ensemble.

### Comment brancher la logique de réponse

`lib/assistant/answer.ts` contient le mode d'emploi. La fonction s'exécute côté
serveur, donc une clé lue dans `process.env` n'atteint jamais le navigateur.

Le fichier liste surtout **les contenus disponibles pour ancrer les réponses** :
57 sessions et 173 chapitres, 792 questions avec leurs explications, les 455
objectifs officiels des six examens, les 18 modules — et le moteur du bac à sable,
qui permet d'**exécuter une requête suggérée avant de la renvoyer** et de ne la
marquer exécutable que si elle passe.

Répondre à partir du contenu de la plateforme plutôt que de la mémoire d'un modèle
est ce qui distingue un assistant utile d'un générateur d'erreurs plausibles.

### Limitation de débit

Deux plafonds sur `/api/assistant/ask` : 40 questions par heure et par compte —
chaque question déclenchera un appel facturé chez le fournisseur branché — et 120
par heure et par adresse, pour qu'une série de comptes jetables ne contourne pas
le premier.

## 4. Migration de base de données

**Une migration est nécessaire avant déploiement :**

```bash
npm run db:migrate
```

Elle crée `assistant_messages`. Sans elle, l'assistant répond mais la transcription
échoue ; la route rend alors la réponse sans identifiant persistant plutôt que de
perdre les deux — l'apprenant obtient sa réponse, l'audit est simplement muet.

Rappel : la table `exam_sessions` du lot précédent exige la même commande.
